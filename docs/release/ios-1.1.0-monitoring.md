# Clovery iOS 1.1.0 发布监控

**执行状态：** `NOT_RUN`

本文件定义首批发布期间的聚合监控与停机条件。指标不得包含用户内容、稳定账户标识、Vault 标识、完整交易材料或设备唯一标识。

## 观察窗口

- 后端迁移/API 部署后至少观察一个完整高峰窗口，再提交 App Review。
- TestFlight 内部和外部测试分别保留独立观察记录。
- App Store 首批分阶段发布后持续观察 bootstrap、权益、同步、照片与崩溃反馈。
- 每次继续放量前，由发布批准人确认没有开放 P0/P1。

## 核心指标

| 域 | 聚合指标 | 停止条件 |
| --- | --- | --- |
| 身份 | claim 签发/消费/重放/冲突、注册事务失败 | 任一跨账户绑定或重复根账户为 P0 |
| bootstrap | pending/needs-attention 数量与持续时间、各阶段完成率 | 数据无法进入原 Vault 或长期不可恢复为 P0/P1 |
| 迁移 | manifest 校验失败、重复、冲突双保留、对象存储失败 | 数据丢失、覆盖或不可恢复为 P0 |
| 权益 | Apple 验证失败、跨账户认领阻止、active/revoked 变化 | 已验证付费用户被锁或串权为 P0 |
| 同步 | pull/push 失败、重试、冲突和重复条目 | 跨设备数据不一致或重复增长为 P0/P1 |
| API | 5xx、延迟、数据库锁、连接池、对象存储错误 | 持续异常且影响登录/迁移为 P1，数据风险为 P0 |
| 客户端 | 启动崩溃、升级崩溃、页面空白、账户删除失败 | 崩溃或删除不可用为 P0/P1 |
| Photos | 保存失败支持编号、拒绝后设置恢复失败 | 可复现保存失败为 P1，广泛失败按 P0 处置 |

## 告警分级

- **P0：** 数据丢失/覆盖、串账户或串 Vault、错误权益、付费用户重新被锁、升级无法启动、生产迁移不可恢复。
- **P1：** 登录方式不可用、照片保存失败、关键操作不可达、重试无法恢复、隐私或商店元数据错误。
- **P2：** 不阻断操作的视觉或文案问题，必须指定后续版本负责人。

任一 P0 立即暂停发布并关闭迁移写入；任一未缓解 P1 阻止继续放量。

## 日志与证据规则

1. 日志只输出错误码、短支持编号、环境、构建号和聚合计数。
2. 身份令牌、密码、恢复码、JWS、收据、日记和照片不得进入日志或监控标签。
3. 受保护查询只在批准的运营工具运行，结果进入加密证据系统，不进入 GitHub Issue。
4. App Store 趋势、销售或购买数只用于聚合观察，不能单独判定某个用户是否已付款。
