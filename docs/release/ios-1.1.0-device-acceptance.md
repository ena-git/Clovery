# Clovery iOS 1.1.0 真机升级验收

**执行状态：** `NOT_RUN`

**执行时点：** iOS 自动化与模拟器完成后、Flutter 开始前

本手册已经准备完成，但必须由两台真实 iPhone 执行。未填写的行不能改成 PASS，模拟器、截图或代码审查不能替代本门禁。

## 安全证据

1. 在仓库外创建权限为 `0700` 的加密证据目录。
2. Device A 升级前完成 Finder 加密备份，并验证备份可读取；不得删除 App 或清理容器。
3. 截图只使用受控测试内容；照片、支持导出和备份不得提交 GitHub。
4. 每项结果只填 `PASS`、`FAIL` 或 `BLOCKED`；失败必须附短支持编号，不附原始响应。

## Device A 旧版本夹具

在 App Store `1.0.3 (14)` 中创建：

- 中文、日文和长文本日记；
- 自定义标签及排序；
- 多张不同分辨率照片；
- 一条不同 ID 但内容相同的日记；
- 一条由批准调试工具形成的同 ID 冲突；
- 非默认字体；
- 可验证的旧购买状态或受控未购买状态。

升级前记录条目数、照片数、标签顺序和字体名称的聚合基线。

## 原位升级流程

1. 不卸载 `1.0.3 (14)`，直接安装签名 `1.1.0 (15)`。
2. 确认原加载页显示，随后只出现一次中文更新公告。
3. 点击“我已知晓”，进入中文登录注册页；iPhone 只显示 CloveryID、Apple 和 Google。
4. 对未绑定 Apple 身份创建自定义 CloveryID，确认 Apple 成为登录方式而非根账户。
5. 等待身份、迁移、权益和 Vault 四阶段完成；中途分别后台、强制终止并重启。
6. 核对旧日记、照片、冲突副本、标签、排序、字体和已购权益均保留。

## 跨设备继承

1. Device B 冷安装 `1.1.0 (15)`。
2. 使用同一 Clovery 根账户的另一已绑定方式或 CloveryID 登录。
3. 核对两台设备的聚合日记数、照片可用数、权益状态和脱敏 Vault 校验值一致。
4. 在 Device B 新建、编辑和添加照片，确认 Device A 收到一次且不重复。
5. 退出并重新登录两台设备，确认云端账户数据不受影响。

| --- | --- |
| Device B 获得同一 Vault 内容 | NOT_RUN |

| 新增/编辑双向同步且不重复 | NOT_RUN |
| 两台设备权益一致 | NOT_RUN |
