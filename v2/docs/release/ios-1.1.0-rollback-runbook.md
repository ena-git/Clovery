# iOS 1.1.0 后端回滚手册

本手册处理账户引导、身份认领、迁移去重或权益继承上线后的异常。目标是先停止新增风险，再恢复兼容服务；默认不对生产数据库执行 `000017`/`000016` down migration。

## 回滚触发条件

出现以下任一情况立即冻结新迁移写入并进入事件响应：

- 登录、注册或旧用户账户继承错误率持续超过发布阈值；
- 同一外部身份可能进入不同 Clovery 根账户；
- 原 Vault、日记或已验证 Apple 权益不可读取；
- `account_bootstrap_jobs` 大量进入 `needs_attention` 或重复创建；
- schema dirty、关键唯一约束缺失、出现孤立身份或 Vault；
- Apple 交易被授予错误账户或跨账户重放未被阻止。

涉及串号、数据丢失或错误权益授予时，视为 P0：停止相关写入口，不尝试在线人工改表。

## 首选回滚：保留版本 17 schema

1. 设置 `MIGRATION_WRITES_ENABLED=false`，暂停账户迁移、身份认领消费和旧权益认领。
2. 保留登录读取、Vault 读取、日记同步读取和已有权益读取；若不能安全区分读写，则临时将 API 切为维护模式。
3. 部署发布前已验证的 API 镜像 digest，不重新构建临时镜像。
4. 保留数据库迁移版本 `17`。`000016` 和 `000017` 为 additive schema，旧 API 不依赖新表和新列。
5. 验证 `/v1/health`、受保护指标、已有 Clovery 登录、已绑定 Apple 登录、Vault 读取和权益列表。
6. 保存脱敏事件时间线和聚合错误数，完整请求、令牌、交易凭证和日记内容进入受控证据系统。

该路径不会删除新表或去重决策字段，也不会让升级窗口内已创建的引导状态丢失。

## 禁止作为第一动作的操作

- 不执行生产 `down` migration；`000017.down.sql` 会删除去重结果字段，`000016.down.sql` 会删除身份认领和账户引导表。
- 不删除账户、Vault、外部身份、交易、权益或迁移记录来“解除阻塞”。
- 不重建 PostgreSQL volume，不以本地开发数据库替代生产恢复。
- 不根据邮箱、设备 ID 或客户端付费标志合并账户或补发权益。
- 不把备份、JWS、身份令牌、恢复码或用户数据上传 Git、工单正文或聊天群。

## 数据库异常路径

### schema 版本 17 且完整

保持 schema，部署旧 API，等待经过评审的前向修复。修复必须在恢复库重放受影响场景并通过完整迁移验证。

### schema dirty 或迁移中断

停止所有 API 实例和迁移任务，保留数据库现场。由数据库负责人比较受保护快照、逻辑备份和当前 catalog，制定前向修复或整库恢复方案。禁止直接修改 `schema_migrations` 掩盖 dirty 状态。

### 已确认不可恢复的数据破坏

只有事件负责人批准后，才从发布前受保护快照恢复到新数据库实例。先在隔离环境验证 SHA-256、关系数量和抽样外键，再切换连接。原数据库只读保留用于取证，不覆盖。

## 仅限可丢弃恢复库的 SQL 降级演练

SQL 降级用于证明备份可读和旧结构可恢复，不用于生产快速回滚：

```bash
cd v2/services/api
DATABASE_URL="$RESTORE_DATABASE_URL" MIGRATIONS_PATH=./migrations go run ./cmd/migrate down
DATABASE_URL="$RESTORE_DATABASE_URL" MIGRATIONS_PATH=./migrations go run ./cmd/migrate down
```

确认版本回到 `15`，旧账户、Vault、密码、Apple 绑定、日记、迁移 staging 行以及 active/revoked 权益仍可读取。随后重新执行 `up` 到 `17` 并运行 `verify-account-bootstrap-migrations.sh`。

## 恢复上线

1. 根因修复通过代码评审、数据库往返演练、race 测试和预发 smoke。
2. 使用新不可变镜像部署，初始保持 `MIGRATION_WRITES_ENABLED=false`。
3. 先验证已有账户和权益读取，再逐步开启迁移写入。
4. 观察至少一个完整发布监控窗口，确认无串号、孤立 Vault、重复权益或引导积压。
5. 事件关闭后更新发布验收记录；只提交聚合结论，不提交用户或交易证据。

## 决策记录

| 条件 | 动作 | 数据库动作 |
| --- | --- | --- |
| 新 API 逻辑异常，schema 完整 | 部署旧 API | 保留版本 `17` |
| 外部依赖暂时不可用 | 关闭迁移写入并重试 | 不降级 |
| schema dirty | 停机、取证、评审前向修复 | 不手工改版本 |
| 已确认数据破坏 | 切换到验证后的恢复实例 | 按事件批准恢复快照 |

未经恢复演练和负责人批准，不得偏离此决策顺序。
